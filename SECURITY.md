# Security reporting

Do not post credentials, personal data, private traces or working exploit details in public issues. Use GitHub private vulnerability reporting on this repository once the maintainer enables it. If it is unavailable, open a public issue requesting a private contact channel without including sensitive details.

Reports should identify the version, affected component, impact and a minimal synthetic reproduction. There is no guaranteed response time or paid security support.

The desktop server is designed for loopback access. Use the authenticated HTTPS deployment adapter for hosted use. The evaluation engine is advisory and cannot guarantee that agent actions are safe or contain already-executed actions.
