IMPROVEMENT WITH DEVELOPER REVIEW

Learn what to test next.

OpenCaliber uses version-comparison evidence to propose additional tests and improvements. Adaptive means improving the review loop—not silently rewriting policies or modifying deployed agents.

Compare the same cases

Give two application-owned agent callbacks isolated copies of the same inputs. Use explicit success assertions and retain the policy fingerprint.

Diagnose the difference

Inspect task regressions, the first invalid tool call, recovery and measurement gaps. A permitted tool call can still lead to an unsuccessful task.

Review the next experiment

Export proposed boundary tests, failure-path tests and improvements. Developers decide what to change, rerun and promote. Initial proposals are deterministic, not trained-model judgments.

CONNECT. OBSERVE. IMPROVE.

Connect once. Monitor each run.

Start with your existing Python script. No edits to individual tool functions.

01 /

Start your console

Download and extract the package. Run python run.py, then open http://127.0.0.1:8787/console. Keep it running.

02 /

Launch your agent

From an environment where OpenCaliber is importable, replace python my_agent.py with the command alongside. Your agent source stays unchanged. Each invocation creates a run under its agent ID.

03 /

Find the call that needs attention

Open Agents Dashboard, search for your agent and select Inspect run or Detected problems. Supported calls are evaluated against console policies after execution. Monitoring coverage shows missing evidence.

04 /

Fix, rerun and review

Correct the agent or its authorized configuration, rerun the same command and inspect the new run. Restore the original startup command to remove monitoring.

Try the included agent first

This example uses SQLite and needs no provider credentials.

# Terminal 1: console package folder
python run.py

# Terminal 2: same folder
python -m opencaliber.connect --agent-id sqlite-demo -- examples/observe_agent/agent.py

For your own agent, use --agent-id my-agent -- my_agent.py.

What gets monitored?

Default SQLite connections and urllib HTTP calls; synchronous Requests and HTTPX calls when installed. No SQL, rows, HTTP bodies, headers or URL paths are captured. Maximum 200 actions per invocation. Async clients, custom SQLite factories, files and child processes are outside coverage. Provider SDK traffic through supported clients appears as HTTP activity.

Need blocking, task success or version comparisons?

The launcher observes; it never blocks, even under a blocking console policy. Business success stays unknown. Use explicit tool integration to add enforcement, selected output evidence, success assertions and linked multi-agent graphs. With shared test inputs and success criteria, Compare agent versions shows which version performed better.

CAPABILITIES AND LIMITS

Built to help you evaluate.
Not to promise perfect safety.

OpenCaliber evaluates captured action metadata against configured checks. The launcher observes supported calls after execution. The optional execution wrapper adds explicit outcomes and pre-dispatch blocking. Neither path undoes actions or proves complete coverage.

What works today

  • Deterministic evaluation of normalized action traces.
  • Console UI, Python API, CLI and SQLite-backed history.
  • Task scope, resource and transfer checks.
  • Configurable limits and a labeled regression suite.
  • Launcher-based observation without tool-function edits; optional wrapper integration for enforcement and richer evidence.

What remains outside coverage

  • Infer arbitrary intent with a trained LLM.
  • Authenticate supplied scope or approval statements.
  • Observe every library, hidden action or child process automatically.
  • Execute containment or guarantee threat prevention.
  • Provide per-user roles or tenant isolation; hosted authentication protects one shared workspace.

BEFORE YOUR FIRST RUN

Frequently asked questions

Does it work with Gemini, Claude, or other agents?

Yes, within the connection coverage. The launcher observes supported synchronous HTTP and SQLite calls regardless of which model your agent uses. It does not capture every SDK, async client or model response. Use Connect an Agent for the launcher and explicit integration options; use selected outputs and success assertions when business-level diagnosis is needed.

What does a risk score mean?

It is the maximum triggered rule severity on a 0–100 scale. It is not a calibrated probability of harm. Review the triggered rules and evidence rather than treating the number as certainty.

Can I use it with a company’s sensitive traces?

The downloaded console binds to loopback and has no login. Hosted deployments protect a shared workspace with authentication and HTTPS, but have no per-user roles or tenant isolation. SDK evidence can be redacted before storage. Review the deployment and privacy documentation before using sensitive traces.

Does passing the test suite mean my agent is secure?

No. These are hand-authored synthetic contract checks for implemented rules. They are not an independent security benchmark, and they do not cover arbitrary attacks, model behavior or hidden history.

What does it cost?

The included deterministic engine requires only Python’s standard library and makes no paid API calls. There is no subscription or billing flow in this preview.
