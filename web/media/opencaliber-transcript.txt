OpenCaliber console walkthrough

00:00:00.000 — Download and start
Connect your existing Python agent to OpenCaliber, without wrapping each tool function. This walkthrough uses the included SQLite example and the current console.
Download the package, extract it, and open a terminal in that folder. Run python run dot py, then open the console on port eight seven eight seven. Keep the console running.

00:00:24.657 — An unchanged Python agent
Here is the example agent. It creates a small in-memory ticket table, inserts a billing ticket, and reads the matching record. The code imports SQLite and a standard context manager. It has no OpenCaliber imports or tool wrappers.
The launcher observes supported library calls around this existing code. It does not need a model API key for this example, and it does not collect SQL text, query parameters, or result rows.

00:00:57.080 — Connect through the startup command
In a second terminal, run the connection command shown here. Set the agent ID to sqlite-demo and pass the path to the included example after the double dash. Enter the command on one line.
The output confirms one matching ticket, three observed actions, and delivered tracking. For your own script, replace the example path and choose a stable agent ID. OpenCaliber must be importable in that Python environment.
To remove monitoring, restore the original Python startup command. Each invocation creates a new run. Child processes need their own launcher.

00:01:37.618 — Connection options in the console
Connect an Agent contains the launcher command, the included example, and coverage details. It is the starting point for connecting an existing script.
The launcher supports default SQLite connections and urllib requests. It also observes synchronous Requests and HTTPX calls when those libraries are installed. Async clients, files, custom SQLite factories, and child processes are outside this coverage.

00:02:07.523 — Find your connected agent
Open Agents Dashboard and search for sqlite-demo. The row shows the latest run, agent version, policy mode, detected problems, and monitoring coverage. History contains the previous invocations.
Observe, Python launcher means policy evaluation happens after execution. This connection never blocks a call, even if the platform policy is set to block violations. A completed process does not establish business success.

00:02:39.327 — Inspect calls and findings
Select Inspect run to see the captured actions and findings. This example records table creation, an insert, and a read. Table creation is an unmapped statement for review; it is not automatically classified as a supported database tool.
A missing task scope means the agent has not supplied its authorized tool scope. This is missing evidence, not proof of fraud or a successful attack. Read the rule, the action identity, and the suggested correction before making changes.

00:03:14.417 — Review monitoring coverage
Monitoring coverage separates missing evidence from detected problems. The launcher does not infer the business objective, fetched record count, transaction success, or multi-agent dependencies.
For task-success assertions, selected outputs, verified tool contracts, or pre-dispatch blocking, use the advanced explicit integration example. Configure only the permissions your application actually requires; do not derive authorization from the calls it happened to make.

00:03:48.653 — Configure checks and improve
Advanced settings holds the platform policy. Review allowed hosts, denied tools, and tool-specific restrictions. Detection capabilities lets you develop and test additional checks. Launcher observations remain non-blocking.
Correct your agent, rerun the same startup command, and inspect the new run. The Developer Guide explains both connection paths. Compare agent versions becomes useful when both versions report shared test cases, success criteria, and outcome evidence.
